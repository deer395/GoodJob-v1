## v1.1 审核修订记录（2026-08-09）

- 将“重复类别事件”收紧为可验证的幂等规则：只有同一 `EmailEvent` 或同一幂等键不得重复产生关联事件；不同邮件即使类别相同，仍由状态机与人工确认共同判断。
- 明确只要岗位存在任一 `Application`，就一律拒绝删除；本批不提供“结束申请后即可删除岗位”的路径，也不新增删除 `Application`。
- 明确恢复第一版仅支持隔离恢复验证和全量替换，不支持合并；补充当前库替换、备份、重启与失败回滚语义。
- 补充 `JobStore.initialize()` 运行期 schema 初始化向 Alembic 显式迁移的过渡与验收要求。

## v1.2 验收修订记录（2026-08-09）

- 无关联申请岗位也必须携带服务端 `confirmed` 参数才可删除；未确认不删除，并显示关联申请数量。存在任一 `Application` 时仍一律拒绝。
- 导出改为显式字段白名单，并对所有导出字符串统一脱敏邮箱地址；不导出 `message_id`，且导出顶层包含 `app_version`。
- 恢复期间持有应用级数据库锁。Web 请求只完成隔离验证、备份和全量替换，并写入“等待重启健康检查”标记；它不得报告恢复成功。下一次应用启动完成 Alembic/schema/外键健康检查后才清除标记并写入已验证记录。
- 每次 Alembic 升级前，如本地库不是 head，自动创建带时间戳的迁移前备份。最新数据安全迁移明确不可逆，必须使用备份恢复。

## v1.3 前台验收补齐（2026-08-09）

- 岗位详情新增“删除岗位”操作：JavaScript 可用时显示原生确认弹窗并先显示关联申请数；不可用时进入服务端确认页。仅关联数为 0 且提交服务端确认参数时才删除。
- 新增前台可发现性与删除确认流程测试。最终人工验收仍需执行一次真实“导出 → 恢复 → 重启应用 → 查看恢复已验证记录”。

## v1.4 第二阶段决策草案｜核心可用性 P1（2026-08-09，待审核）

### 用户目标

用户应能在不构造 URL、不猜测隐藏能力的前提下：

- 从秋招雷达快速切换到自己当前要处理的岗位集合，并立即知道正在使用的条件和结果数量；
- 在真实校招长公司名、长岗位名场景下，稳定点击“查看详情”等主操作；
- 主动同步邮箱时理解正在做什么、扫描了什么、结果如何；失败时能看到不含敏感信息的原因类别和下一步。

### 范围、页面与字段

1. **雷达筛选入口（`/jobs`）**
   - 可见快捷筛选：临期、今日新增、本周截止、收藏、高匹配、待评估；保留既有搜索和排序。
   - 页面显示：当前快捷筛选标签、搜索关键词（若有）、排序方式、结果数，以及“一键清除筛选”。
   - 不新增岗位、画像、匹配分或导入数据字段；仅复用既有 `state`、`q`、`sort` 与列表统计。
2. **岗位长标题与操作区布局（`/jobs`、现有 CSS）**
   - 卡片标题可在桌面端最多两行截断，完整公司/部门/岗位/城市信息仍在详情中可见。
   - 操作区（特别是“查看详情”）保持不可压缩的最小可点击尺寸；移动端改为内容纵向堆叠，按钮全宽或易触达。
   - 不改变岗位详情字段、投递动作、删除安全确认或匹配逻辑。
3. **邮件同步诊断可用性（`/progress?view=email` 与本地同步接口）**
   - 显示最后一次同步的时间、结果类别、扫描范围（本地 INBOX、近 7 天）及候选/新增/去重计数；这些为本地诊断元数据，不保存邮件正文、邮箱地址或凭据。
   - 同步中按钮禁用并显示进行中；并发点击只运行一次。
   - 成功反馈显示扫描范围和计数；失败反馈只显示诊断类别（例如未配置、鉴权/权限、超时、连接、未知），并提供“重试”和“检查本地配置”入口。
   - 可新增最小的本地同步状态记录字段/表，仅保存上述非敏感诊断元数据；不得改变 `EmailEvent`、申请状态机、邮件解析结果或关联策略。

### 雷达快捷筛选语义

- 六个快捷筛选为：`临期`、`今日新增`、`本周截止`、`收藏`、`高匹配`、`待评估`。
- 快捷筛选之间**互斥**：一次只激活一个 `state`，点击另一快捷筛选即替换当前快捷筛选；“一键清除筛选”移除快捷筛选和搜索词，并恢复默认排序。
- 搜索词 `q` 与当前快捷筛选**组合（AND）**：例如“本周截止 + 搜索‘算法’”只显示同时满足本周截止和文本匹配的岗位。排序 `sort` 只决定结果顺序，不改变筛选集合。
- 精确定义：
  - `临期`：岗位 `deadline` 非空，按本地日期从今天至未来第 3 天（含）截止；已逾期岗位不在此集合。
  - `今日新增`：岗位 `created_at` 的本地日期等于今天。
  - `本周截止`：岗位 `deadline` 非空，按本地日期从今天至本周日（含）截止；已逾期岗位不在此集合。它可以与“临期”重叠，但快捷筛选不同时激活。
  - `收藏`：`is_favorite = true`。
  - `待评估`：岗位状态为 `待评估`。
  - `高匹配`：仅当求职画像已满足既有规则匹配配置条件时可用，且既有 `match_score >= 70`；画像未配置时入口显示为不可用提示，不查询、不显示“0 个高匹配”，也不得触发 AI。

### 邮件同步运行、降级与扫描口径

- 固定扫描范围：本地 `INBOX`、近 7 天、最多 50 封候选邮件；本阶段不允许页面修改这三个参数，也不扫描其他文件夹或邮箱。
- JavaScript 可用时：提交同步表单后立即禁用按钮、显示“正在同步…”，直到服务端响应/重定向完成；再次点击不应提交第二个请求。
- JavaScript 不可用时：普通表单提交仍可工作；服务端互斥锁拒绝并发/重复请求，返回“同步正在进行，请勿重复点击”的可读反馈，而不是启动第二个 Agent。
- 无论正常完成、子进程超时或异常，服务端必须在 `finally` 中释放同步锁；锁释放后用户可重试。
- 候选、新增、去重计数来源必须可测试且口径一致：
  - `候选`：本次 Agent 在固定扫描范围内识别为候选的邮件总数；
  - `新增`：本次调用 `/api/email-events` 成功创建的 `EmailEvent` 数；
  - `去重`：候选数减新增数，代表已由本地去重键拦截、未重复写入的候选数。
  Agent 或接口无法给出完整计数时必须显示“计数不可用”，不得编造 0。

### 最近一次同步诊断记录

- 只保留**最近一次**同步诊断（后一次成功、失败或超时均覆盖前一次）；不保存完整运行日志或历史邮件列表。
- 最小字段：`started_at`、`finished_at`、`outcome`（`success` / `failed` / `timeout` / `busy`）、`diagnostic_category`、`scan_mailbox`（固定 `INBOX`）、`scan_days`（固定 `7`）、`scan_limit`（固定 `50`）、`candidate_count`、`created_count`、`deduplicated_count`、`parser_enabled`。
- `diagnostic_category` 仅允许：`not_configured`、`authentication_or_permission`、`connection`、`timeout`、`agent_unavailable`、`unknown`、`none`；页面映射为中文可读说明。
- 明确禁止保存或展示：邮箱地址、IMAP 主机/端口、授权码、密码、API Key、完整命令行、原始 stdout/stderr、邮件主题/正文/附件、邮件 `message_id`、UID 或任何可还原个人邮箱身份的内容。

### “检查本地配置”入口

- 邮件同步失败反馈中的“检查本地配置”链接到一个新的本地说明页（建议路径：`/email-sync-help`），而非暴露 `.env` 内容。
- 说明页仅展示所需变量名称、是否已配置/缺失的布尔状态、固定扫描范围、授权码安全提醒、启动 Agent 的本地命令示例与“返回邮件待确认 / 重试同步”入口。
- 说明页不得回显变量值、邮箱地址、IMAP 主机、端口、授权码、API Key 或完整错误输出。

### 主操作

- 雷达：点击快捷筛选；点击“一键清除筛选”回到默认列表。
- 岗位：点击稳定可见的“查看详情”；详情中保留既有主操作。
- 邮件：点击“同步邮箱”；失败后点击“重试”或进入本地配置说明。

### 成功与失败反馈

- 筛选成功：例如“当前：本周截止 · 共 12 个岗位”；清除后明确显示“已清除筛选”。
- 长标题：主按钮始终可点击；完整标题仅在详情中展示，不因截断丢失信息。
- 同步成功：例如“已检查本地 INBOX 近 7 天（最多 50 封）：候选 8 封，新增 2 封，重复 6 封。”
- 同步失败：例如“同步未完成：本地 IMAP 未配置。未创建或修改任何申请。”并提供明确下一步；不得回显主机、授权码、邮箱地址、命令输出或邮件正文。

### 异常与边界场景

- 快捷筛选和关键词同时存在时同时生效；无结果仍显示当前条件和清除入口；高匹配在画像未配置时不可误导为可用结果。
- 超长中文、英文、无空格标题、缺失城市/DDL、窄屏和 200% 缩放不得使主操作被遮挡或无法点击。
- 邮件同步双击、并发请求、JavaScript 不可用、子进程超时、缺少配置、权限失败、网络失败或不可识别输出：不得重复运行、不得改变申请状态，且记录/展示安全诊断类别；超时和异常后必须释放服务端锁以允许重试。
- 旧的同步记录缺失时显示“尚未同步”，不阻断现有待确认队列和手动流程。

### 明确非目标

- 不进入第三阶段；不修改 AI 匹配分、规则匹配、AI 提示词、邮件解析模型/规则、解析字段、关联状态机或自动关联阈值。
- 不实现后台定时同步、IMAP 守护进程、多邮箱、邮件全文保存、推送、外部日历同步、OCR、自动投递或批量 AI 分析。
- 不进行无关视觉重构、前端框架迁移或领域模型重写。

### 可自动化验收标准

1. `/jobs` 可通过正常链接访问六个快捷筛选；页面显示当前筛选、结果数和清除链接；关键词与筛选可组合，空结果仍可清除。
2. 至少覆盖临期、今日新增、本周截止、收藏、高匹配、待评估的查询口径；高匹配在画像未配置时安全降级。
3. 含超长无空格标题的岗位卡渲染后仍含“查看详情”可点击控件；CSS 具备桌面最小操作区、两行截断和窄屏堆叠规则。
4. 邮件同步在 JavaScript 可用时按钮立即禁用，在不可用时仍由服务端锁拒绝第二次执行；成功、超时和异常后锁均释放，下一次请求可重试。
5. 成功结果保存/呈现固定范围（INBOX、近 7 天、最多 50 封）与具有可测试来源的候选、新增、去重计数；计数不可得时明确显示不可用。
6. 未配置、鉴权/权限、超时、连接和未知失败映射为安全诊断类别；页面提供重试与 `/email-sync-help` 本地配置说明入口；响应和持久化记录不包含授权码、邮箱地址、邮件正文、`message_id`、UID 或子进程原始输出。
7. 同步失败或诊断展示不改变 `Application`、`EmailEvent` 关联状态、邮件分类或解析字段；最近一次诊断只保留规定的最小字段并覆盖旧记录。

### 手工验收步骤

1. 打开秋招雷达，依次点击六个快捷筛选；确认条件、结果数、清除入口可见，并用搜索词叠加验证。
2. 导入或手工创建至少一条极长公司名/岗位名记录；在桌面、窄窗口与手机宽度下确认“查看详情”始终可点击，详情显示完整标题。
3. 在邮件待确认页点击同步：观察按钮进入进行中状态；禁用 JavaScript 后重复提交，确认服务端提示进行中而非第二次执行；成功时核对 INBOX、近 7 天、最多 50 封和三个计数。
4. 分别在缺配置、无权限/鉴权失败与超时场景下同步；确认只展示安全诊断、锁会释放、存在重试与 `/email-sync-help` 入口，且申请与邮件队列状态不变。

## 1. 用户目标

用户在使用岗位池、投递工作台、申请进度与本地邮件同步时，应能确信：

- 一封误判、迟到或重复邮件不会静默改变既有申请历史；
- 删除岗位不会让关联申请和事件从视图中“消失”或留下不可恢复的孤立数据；
- 用户可导出不含凭据和敏感原文的完整结构化数据，并能在隔离数据库中恢复；
- 已有的雷达筛选、主操作和本地邮件同步功能易发现、易理解、失败时可诊断。

最终投递、状态确认、邮件关联与恢复操作均仍由用户主动触发和确认。

## 2. 范围与分阶段优先级

### 第一阶段：P0 与数据安全相关 P1（本卡获批后首先实现）

1. **P0-01 邮件自动关联状态安全**
   - 自动关联仅针对“公司与岗位精确一致、唯一候选、高置信、当前状态允许推进”的申请。
   - 自动和人工确认共用同一状态机校验；已结束、目标阶段冲突或任一歧义均进入待确认队列，不推进状态。
   - 同一 `EmailEvent` 或同一幂等键只能成功产生一次关联事件；重复同步、重复点击或并发请求必须幂等。不同邮件的同类事件不因类别相同被一概拒绝，仍按状态机与人工确认判断。
2. **P1-01 岗位删除数据完整性**
   - 第一版采用“存在任一 Application 时一律禁止删除岗位”的保守策略，而非级联硬删；页面显示关联申请数量，但不提供通过结束/处理申请后删除岗位的路径。
   - 无关联申请的岗位可在二次确认后删除；所有删除在事务中完成。
3. **P1-02 全量数据导出与恢复**
   - 提供本地 JSON 全量导出入口和受控恢复入口/命令说明；导出覆盖岗位、画像、申请、申请事件、检查项、导入批次、AI 设置、已持久化的脱敏邮件结构化事件及必要版本元数据。
   - 绝不导出 API Key、AI/IMAP 授权码、邮箱地址、完整邮件正文、附件、截图原图或原始模型响应。
   - 恢复第一版只支持隔离恢复验证与全量替换，不支持将导出数据合并进当前库；导入前创建备份，先校验格式、版本和引用完整性，失败则不部分写入。
4. **数据库迁移与备份基线**
   - 将本批新增/修正的 schema 演进纳入可执行、可测试的迁移路径；不再以运行期隐式 schema 漂移替代正式迁移。
   - 对不可逆数据变更先创建本地备份，并在恢复说明中标明回退边界。

### 第二阶段：核心可用性 P1（第一阶段验收后实施）

5. **P1-03 雷达筛选入口**：将临期、今日新增、本周截止、收藏、高匹配、待评估等已有视图呈现为可见筛选入口；显示当前条件、结果数与“一键清除”。
6. **P1-04 长标题与主操作布局**：岗位卡标题限制为两行、完整标题在详情保留；操作区有最小宽度，窄屏按内容堆叠；导入中的多岗位串联只提示人工拆分，不将其自动拆成可投递记录。
7. **P1-05 邮件同步状态**：在不保存正文和凭据前提下显示本地配置检查、上次成功同步、扫描范围、候选/新增/去重计数、可操作错误和重试入口；真实 IMAP 鉴权/联通失败以集成验收覆盖。

### 第三阶段：仅记录方案，**不在本批实现**

- **AI 匹配升级**：先设计“硬规则 → 结构化证据 → 可解释排序 → AI 补充语义缺口”的统一评分卡、纠错记录和离线评估样本；规则分与 AI 辅助判断不得互相覆盖。
- **邮件解析升级**：先设计分步可观测性、解析版本、人工修正与回归样本集；任何低置信分类、公司/岗位/时间提案保持待确认，不自动写入申请状态或日历。
- OCR、IMAP 守护同步、多邮箱、邮件全文存储、外部日历同步、自动投递和批量 AI 分析均不在本批范围。

## 3. 数据字段、迁移与备份

### 既有数据的约束修整

- `Application.status` 继续使用：`待投递`、`已投递`、`测评/笔试`、`面试`、`Offer`、`已结束`。
- `EmailEvent.status` 保留：`pending`、`auto_applied`、`confirmed`、`dismissed`、`parse_failed`、`linked_manual`；新增的安全判断不以“自动成功”掩盖歧义，而是保留 `pending` 与可读原因。
- 为邮件关联事件保存最小的幂等依据（源 `email_event_id` 或明确的独立幂等键），建立唯一性或事务内重复检查；不得以“同类别”作为跨邮件去重依据，也不保存原邮件全文。
- 删除策略不引入级联删除 Application、ApplicationEvent、Checklist 或 EmailEvent；只要 `JobPosting` 存在任一关联 `Application`，删除请求一律被拒绝。

### 导出格式

- 顶层包括 `format_version`、`exported_at`、`app_version` 和数据集合；时间采用 ISO-8601，枚举使用当前中文状态值。
- 导出仅保存恢复所需的主键与关系键，并在导入时验证岗位—申请、申请—事件、邮件—申请事件等引用。
- 未来字段新增须向后兼容；未知字段忽略并记录可读警告，缺失必需字段或引用损坏则拒绝恢复。

### 迁移/备份方案

1. Alembic 升级前，只要本地库不是 head，就自动创建带时间戳的本地 SQLite 迁移前备份；升级失败时保留原库和该备份。
2. 使用 Alembic 显式迁移版本表与 `upgrade`；若无法安全 `downgrade`，迁移文件标记不可逆并说明恢复方式。
3. 过渡期内，`JobStore.initialize()` 仅负责连接初始化和验证数据库已达到目标迁移版本，不得继续隐式新增/修改业务 schema；新库创建与已有库升级均必须经 Alembic 路径覆盖。
4. 恢复先在临时/隔离数据库完成 schema 与数据校验。验证通过后，持有应用级数据库锁、备份当前目标库，再以恢复库**全量替换**目标库；不执行表级、记录级或字段级合并。
5. Web 请求无法安全终止并重启自身，因此替换后只写入“等待重启健康检查”标记，不得报告恢复成功。下一次启动必须执行 Alembic、schema 与外键健康检查；通过后才写入已验证记录并清除标记。检查失败时保持未验证状态，用户须从替换前备份回滚；原库和备份均保留。
6. 不在日志、错误页或导出文件中输出密钥、授权码、邮箱地址、邮件全文或完整模型输入输出。

## 4. 状态流转与操作规则

### 邮件自动关联

```text
同步候选邮件
  → 解析/本地回退提案
  → 仅在唯一精确 + 高置信 + 允许状态迁移 + 未重复事件时自动关联
       → 写入一个 ApplicationEvent → 更新为合法目标阶段 → EmailEvent=auto_applied
  → 任一条件不满足
       → EmailEvent=pending → 用户确认关联 / 手动补记 / 驳回
```

- 已结束申请绝不被邮件自动或普通确认操作重新推进。
- 不允许的回退和跨阶段冲突不改变申请；同一 `EmailEvent` 或同一幂等键的重复请求不再创建第二个事件。不同邮件的同类事件由状态机和人工确认决定是否可写入；页面解释原因并保留人工处理入口。
- 用户人工确认可在表单中明确选择合法目标申请及候选时间；人工确认优先于提案，但仍经过状态机和幂等校验。

### 岗位删除

```text
删除岗位 → 查询关联 Application 数
  → 未携带服务端确认参数：拒绝删除，显示关联申请数量
  → 大于 0：一律拒绝删除，说明不会删除申请历史，并提供查看关联申请入口
  → 等于 0 且已确认：事务删除岗位 → 返回岗位池成功提示
```

### 导出恢复

```text
用户点击“导出全部数据” → 下载脱敏 JSON
用户选择恢复文件与目标库 → 格式/版本/关系校验 → 持有应用级写入锁 → 创建目标库备份
  → 在隔离库恢复验证通过：全量替换目标库 → 写入等待重启检查标记 → 提示必须重启，不报告成功
  → 下一次启动健康检查通过：清除标记并写入已验证记录
  → 校验、替换或启动检查失败：不保留部分恢复结果；启动检查失败保持未验证并提示从替换前备份回滚
```

## 5. 页面主操作与反馈

- 岗位池：筛选条位于列表上方；清晰区分筛选、查看详情与“准备投递”主操作。
- 有关联申请的删除：确认对话框/反馈明确写明“为保护申请历史，只要存在申请，本岗位一律不能删除”，不得呈现看似成功的删除状态；本批不提供通过结束申请或删除申请解除限制的入口。
- 数据管理：提供“导出全部数据”主入口；恢复为次级、危险操作，仅提供“隔离验证后全量替换”，需选择文件与确认目标，完成后展示恢复计数、替换前备份位置和重启/健康检查结果。
- 邮件待确认：同步按钮在运行期间禁用；完成时说明扫描范围和结果，失败时显示不含敏感信息的诊断类别及“重试/检查本地配置”入口。
- 所有成功反馈说明实际副作用；失败反馈说明没有改变哪些数据并给出下一步。

## 6. 异常、重复与安全场景

- 多个精确岗位匹配、公司/岗位缺失、低置信分类、过期/已结束申请、未知邮件类别：不自动推进，保留待确认。
- 同一 `EmailEvent` 或同一幂等键的重复同步、重复点击和并发请求：不产生第二个关联事件。不同邮件的同类事件不按类别去重，而按状态机和人工确认处理。
- 目标申请不存在、已被删除、状态已被其他操作改变：拒绝确认并重新渲染最新状态。
- 导出目录不可写、磁盘空间不足、JSON 损坏、版本不兼容、主键冲突、关系缺失、恢复中断：不覆盖原库，显示恢复/备份路径与修正建议。
- 删除请求中的不存在岗位、已关联岗位、重复提交：均可预测地返回，不产生孤立记录。
- 迁移失败、旧库缺字段：保留原库、停止启动中的写操作或切换，并提供可读恢复指导；不静默尝试数据修复。

## 7. 非目标

- 不新增邮件正文保存、邮箱地址持久化、自动轮询、后台守护进程或自动回复。
- 不自动创建岗位/申请、不自动提交投递、不将 AI 或解析结果直接当作用户最终判断。
- 不进行 OCR、邮件全文语义检索、AI 匹配算法替换、批量 AI 分析、跨设备同步或云端账号。
- 不做与本卡无关的 `app.py` 大型重构或前端框架迁移。

## 8. 验收标准

### 第一阶段（必须自动化覆盖）

1. 高置信但目标为已结束、状态冲突、非唯一匹配，或同一 `EmailEvent` / 同一幂等键重复请求的邮件，不会改变 `Application`，且邮件保留为待确认。不同邮件的同类事件不按类别去重，仍由状态机与人工确认决定。
2. 合法唯一邮件仅创建一次 `ApplicationEvent`；重复同步/重复请求不产生第二个事件。
3. 人工确认也不能把已结束申请重新推进，不能绕过状态机；失败后邮件和申请数据保持原样。不同邮件的同类事件不因类别相同被拒绝，而由状态机与人工确认决定。
4. 删除无申请岗位须经服务端确认参数才可成功；未确认时不删除且显示关联申请数量。只要存在任一关联申请，删除一律被拒绝，岗位、申请、事件和检查项均仍可查询；本批不提供删除 Application 或通过结束申请解除该限制的路径。
5. 导出使用显式字段白名单并含 `app_version`；不包含 API Key、AI/IMAP 授权码、`message_id`、邮箱地址、完整正文、附件或截图原图。
6. 在新建隔离 SQLite 库中恢复导出后，岗位、画像、申请、事件、检查项、导入批次、脱敏邮件事件及关系计数一致；第一版只允许验证后全量替换，不支持合并；坏文件恢复不会修改目标库。
7. 替换恢复前必有目标库备份；Web 替换后只显示“等待重启健康检查”，不得提前显示恢复成功。下一次启动通过健康检查后才标记成功；失败时保留回滚提示与替换前备份。
8. `JobStore.initialize()` 到 Alembic 的迁移路径在空库、已有库、迁移失败和不可逆迁移场景均有测试/启动检查；每次非 head 升级前自动备份，运行期初始化不再造成隐式 schema 漂移。

### 第二阶段（在第一阶段完成后验收）

9. 雷达无需构造 URL 即可访问临期、今日、本周、收藏、高匹配和待评估筛选；当前筛选和结果数可见且可清除。
10. 超长标题桌面不挤压主操作，窄屏不溢出；详情仍可查看完整标题。
11. 同步页显示上次结果和非敏感失败原因；并发点击只执行一次，IMAP 配置/超时/权限失败均给出可行动反馈，且不改申请状态。

## 9. 最小验证与成功阈值

- 以现有真实但脱敏的邮件样本和申请状态组合做回归：P0 场景 100% 不发生非法推进。
- 导出→隔离恢复→计数与抽样关系核对连续执行 3 次均成功，且敏感字段扫描为 0。
- 5 条超长标题与 3 个窄屏宽度下，主操作均可点击且无横向布局遮挡。
- 使用真实本地 IMAP 配置进行一次成功同步和至少三类失败演练（缺配置、鉴权/权限、超时）；仅记录结果类别，不记录凭据或正文。

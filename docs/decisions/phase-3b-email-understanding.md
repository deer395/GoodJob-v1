# 决策卡：Phase 3B｜可解释的招聘邮件理解

状态：已实现，待人工验收。版本：v1（2026-08-12）。

## 用户目标

用户同步本地邮箱后，应能看懂一封招聘邮件与哪份申请可能相关、它带来了哪些候选事件、下一步要做什么，以及系统依据邮件中的哪句话得出该提案；只有用户确认后，申请阶段、事件时间和行动截止才写入正式进度。

## 范围与数据边界

- 继续由用户主动运行一次本地、只读 IMAP 同步；不增加后台监听、定时扫描、飞书推送、多邮箱或自动提醒。
- 完整邮件正文只在本地 Agent 的进程内用于挑选相关句子；数据库仍只保存标题、发件域名、脱敏摘要和脱敏证据片段，不保存正文、附件、邮箱地址、授权码、原始模型输入输出或会议令牌。
- 外部 LLM 仅在用户已启用邮件 AI 解析后接收标题、发件域名和最多 8 条脱敏证据句；每条证据有本地编号。模型不接收完整正文。

## 解析与状态

- 一封邮件可提出零到多个候选事件，每个事件包含：类型（笔试、面试、Offer、拒信、补充材料、提醒、改期/取消、其他）、候选安排时间、候选行动截止、建议下一步、置信度和证据句编号。
- 公司、岗位、城市仍仅在邮件明确出现时提案；关联申请为带理由的候选，不是事实。
- 笔试、面试、Offer、拒信可由用户逐项确认，并且必须复用既有状态机与幂等约束后才创建一个 `ApplicationEvent` 和更新申请状态。
- 补充材料、提醒、改期/取消和其他只作为待人工处理提案：本版本不得自动或一键改写既有申请事件、安排时间或阶段。
- 每个候选事件独立确认或驳回；同一封邮件可确认多个不同事件，但同一候选事件不可重复写入。

## 主操作与反馈

- 邮件待确认页按邮件展示“系统读到什么 / 依据什么 / 建议确认什么”。用户可为每个候选事件选择申请、确认候选时间、编辑下一步，并确认或驳回。
- 未能解析、字段不明确、多个申请候选、阶段冲突或已结束申请均保留待确认并说明原因；不得静默降级为自动推进。
- 用户修正或确认时，保存最小的提案与最终结果，供后续回归测试；不保存完整正文。

## 明确非目标

- 不自动投递、自动回复、自动创建岗位或申请；不把低置信或模糊关联写入申请状态。
- 不实现外部日历同步、提醒、冲突提醒、全文检索、附件/OCR、向量检索或新的模型供应商。
- 不修改岗位匹配主排序或 Phase 3A 结论。

## 验收标准

1. 本地候选筛选可依据主题或正文中的招聘信号进入处理，同时不保存完整正文；脱敏证据片段不含邮箱、手机号或 URL 参数。
2. 模型输出最多 3 个严格 schema 校验的候选事件；无效 JSON、未知类型、无证据编号或非法时间均安全失败并进入人工路径。
3. 一封“通过筛选 + 测评截止”邮件可呈现阶段事件和行动截止两个候选项；用户可仅确认其中之一。
4. 改期、取消、提醒和补充材料可呈现为人工处理项，不能自动改写既有申请或事件。
5. 已结束、冲突、非唯一匹配、重复确认及重复同步均不会造成非法阶段推进或重复事件。
6. 邮件 AI 关闭、服务失败或本地回退时，手动确认与补记路径仍可用。

## 实施记录

- 已新增 `email_event_proposals`，以独立记录保存多个脱敏、带证据的候选事项；确认与驳回均逐项进行。
- 已实现正文信号的本地候选召回、脱敏证据句、结构化多事项 LLM 输出，以及阶段推进/行动截止的状态机确认路径。
- 改期取消、提醒、补充材料和其他事项均明确停在人工处理边界，不能自动改写申请状态或既有事件。
- 自动化验收：`84 passed, 1 warning`；真实 IMAP、真实模型输出质量与页面人工可理解性仍待用户验收。
- 新增一套 12 封完全虚构、脱敏的邮件理解标准题，覆盖阶段推进、截止、改期取消、材料、提醒、多事件、模糊关联、广告排除与提示注入；稳定测试不调用模型，`--live` 评测才会使用用户当前配置的模型并输出可比较结果。
- 真实 provider 复测（DeepSeek，合成集）：关闭邮件解析的推理输出并提高专用输出额度后，11/11 候选邮件返回结构化结果，11/11 时间与证据引用正确，10/11 事件类型/阶段符合标准答案；唯一偏差为“明确的面试取消”被识别为“改期取消 + 其他”而非“改期取消 + 面试”。该类提案仍只能人工处理，未造成自动状态写入。
- v1.1 界面收敛已获用户确认：邮件首屏只显示一个主结论、下一步与一次主确认；摘要、置信度、证据和其他候选项均进入按需展开区。没有明确行动截止时间的“行动截止”提案会在写入前降级为“提醒”，不得作为截止驱动的确认项展示。
- 长招聘通知修正：本地证据会将“编号标题 + 紧随的值”合并，例如面试时间/地点/岗位；材料清单会作为一个有上限的证据单元保留。面试主提案可保存明确地点，并把明确地点与回复截止复述在首屏下一步中，用户无需先展开证据。
